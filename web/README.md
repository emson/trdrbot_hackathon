# trdrbot.com

The public site, generated from trdrbot's own live record. A SvelteKit 5 app,
prerendered to static HTML via `@sveltejs/adapter-static` and deployed to
Cloudflare Pages.

Nothing on this site is hand-written data. Every number, trade, decision and
note comes from `web/src/lib/data/snapshot.json`, which is generated by the
Python exporter at `src/trdrbot/site_export.py` (run from the repo root, not
from here) reading the agent's journal, ledger, wiki and blog directly.

## Quick start

From this directory (`web/`):

```bash
npm install        # first time only
npm run dev         # dev server with hot reload, http://localhost:5173
```

To see the actual production build (what really ships — dev mode skips
prerendering, so it can hide build-only bugs):

```bash
npm run build
npm run preview     # serves build/, http://localhost:4173
```

**If you rebuild while a `preview` server is already running, restart it.**
`vite preview` doesn't reliably notice a `build/` directory that changed
underneath it — you'll get a page whose HTML references a CSS/JS file hash
that no longer matches what's on disk, and the page loads with no styling at
all (content renders, layout doesn't). Kill it and start a fresh one after
every `npm run build`:

```bash
# macOS/Linux
pkill -f "vite preview" ; npm run preview
```

## Refreshing the data

The site reads a **committed** snapshot file, so `npm run build` never
requires Python or the trading loop to be running. To pull in the agent's
latest decisions before a rebuild, run this from the **repo root** (one level
up), not from `web/`:

```bash
cd ..
uv run trdrbot site export
cd web
npm run build
```

The exporter refuses to write (and prints why) if it finds anything
credential-shaped in the export, or if the record has shrunk since the last
snapshot — both are meant to stop, not to be worked around.

## Syncing the standalone documents

`docs/deck.html`, `data/report.html` (the Coach), and the two risk-appetite
pages are hosted as-is under `static/`, with a small back-link banner
injected. Re-sync them after they change:

```bash
node scripts/sync-static.mjs
```

## The full publish cycle

`../scripts/publish.sh` does export → sync-static → build → verify → deploy
→ log, and is safe to run on a timer (it's lock-guarded and a no-op if
nothing changed). See that file for what each step checks before it will
deploy.

## Project structure

```
web/
├── src/
│   ├── app.html, app.css        shell + the whole design system (ported from docs/deck.html)
│   ├── lib/
│   │   ├── data/snapshot.json   generated - do not hand-edit
│   │   ├── components/          shared UI (charts, pills, cards, nav...)
│   │   ├── site.config.js       repoUrl / videoUrl / frozen - fill these in
│   │   └── format.js, glossary.js
│   └── routes/                  one folder per page; +page.js loads a slice
│       of snapshot.json, +page.svelte renders it
├── static/                      images, favicon, the synced standalone docs
└── scripts/sync-static.mjs
```

**Rule enforced throughout:** `snapshot.json` is imported only inside
`+page.js`/`+layout.js` `load()` functions, never inside a `.svelte`
component or a shared module — that's what keeps it out of every page's own
JS chunk. If you add a route, follow the same pattern rather than importing
the snapshot directly into a component.

## Before it's really live

Two things in `src/lib/site.config.js` are still empty and gate their own
UI (a CTA is omitted, never rendered as a dead link, when its value is
unset):

- `repoUrl` — once the GitHub repo is public
- `videoUrl` — once the demo video is recorded

Domain and hosting setup (Cloudflare Pages, DNS, Namecheap nameservers) is
handled by the `awf-*` skills from outside this directory - see
`docs/website_build_transcript.md` §8 in the repo root for the exact
sequence.
