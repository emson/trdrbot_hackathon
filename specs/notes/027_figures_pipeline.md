# 027 - One command, one set of figures

Audience: an LLM implementer with full repo access. The problem, the design, why
the alternatives lost, the edge cases with their required handling, and the
tests that must exist.

Plain dashes throughout. No em dashes in code, docs or prompts.

## 0. What already exists (read this before proposing anything)

Most of the pipeline is built. The gap is narrower than it looks.

| Piece | State |
|---|---|
| `agent/src/trdrbot/site_export.py` | **Works.** Writes `web/src/lib/data/snapshot.json`: account, competence + the earned ladder, book greeks, calibration, attribution, equity curve, positions, ledger items, notes, journals, docs, `counts`, `integrity` |
| Monotonicity guard (`_check_monotonic`) | **Works.** Refuses to publish if positions / journal_rows / theses shrank |
| Redaction scan (`redaction_scan`) | **Works.** Refuses to publish if a secret reached the export |
| Stable `generated_at` (I-114) | **Works.** Only re-stamped when the payload actually moved, so a no-op is detectable |
| `scripts/publish.sh` | **Works.** Lock, no-op detection, report -> export -> sync-static -> build -> verify -> deploy, with a JSONL log |
| `web/scripts/sync-static.mjs` | **Works.** Copies the standalone documents into `static/`, and (since the assets fix) mirrors `docs/assets/` |
| Svelte site | **Works.** Reads `snapshot.json`, renders live figures with provenance |

**So there is already a JSON document and already a one-command publish.** Do
not rebuild either.

## 1. The actual gap

**`docs/deck.html` carries ~16 hand-typed figures that duplicate numbers the
snapshot already owns.** They were last updated by hand on 2026-09-03. They will
go stale silently, and the deck is the submission artifact.

This is the project's single most documented bug class, arriving in a new place:
two EV loops (D-074), two clocks (D-074), two calibration numbers (D-076), the
ladder caps hardcoded in `CompetenceLadder.svelte` (fixed by shipping them as
data). The deck's figures are the same defect - a second copy of a number that
drifts - and nothing checks it.

Three smaller gaps ride along:

1. **Repo facts are computed nowhere.** The deck quotes test count, lines of
   Python, issue count and scaffold count. Each was derived by hand, once.
2. **`docs/deck.pdf` is not regenerated by `publish.sh`.** The command is
   documented in `web/CLAUDE.md` and run by hand, so the PDF drifts from the HTML.
3. **Nothing checks that a document agrees with the record.** That is the
   "check our documents and thesis counts" half of the request.

### The gap is already producing a defect

`docs/deck.html` says **"125 numbered issues so far"**. Two defensible readings:

| reading | value |
|---|---|
| highest issue id ever assigned | **125** |
| entries currently listed in `specs/issues.md` | **75** |

Both are computable, both are honest, and nothing declares which one the deck
means. That is a figure needing a *named definition*, not a re-derivation each
time someone edits the slide. Any design here must make the definition the
artifact, not the number.

## 2. Empirical validation, before the design

Every trading figure in the deck was checked against the live snapshot using the
site's own formatters. **Twelve of twelve reproduce byte-identically:**

| figure | snapshot -> formatted | deck says |
|---|---|---|
| equity | `$114,085` | `$114,085` |
| return | `+14.1%` | `+14.1%` |
| positions / open / traded / declined | 11 / 2 / 9 / 145 | same |
| theses | 185 | 185 |
| calibration n / n_eff / resolution | 76 / 9.8 / 0.000 | same |
| tick | 821 | 821 |
| tier | `scale` | SCALE |

The derived P&L range across closed positions computes to **−2.9% to +129.1%**,
matching the deck exactly. Repo facts compute cleanly too: 7 scaffolds, 22,885
lines (deck rounds to 22,900).

**The snapshot already contains everything the deck needs.** No new data source
is required. This is a wiring problem, not a collection problem.

## 3. Design: tagged figures, injected, with the source left viewable

A figure in the deck becomes an element that declares which number it is:

```html
<span class="big" data-figure="account.equity" data-format="usd0">$114,085</span>
```

An injector rewrites the **text content** of every `data-figure` element from
`snapshot.json`. The baked text is a real, correct, last-known value.

Why that shape:

- **The source stays viewable.** `docs/deck.html` is a standalone document,
  hosted as-is at `trdrbot.com/deck.html` and opened directly from `docs/`.
  Placeholders would render as literal `{{equity}}` to anyone opening it.
- **Injection is idempotent.** It rewrites text; the attribute survives.
- **Drift becomes detectable.** Baked text versus computed value *is* the
  document check. `--check` reports it and exits non-zero.
- **The PDF works.** Inject first, render second; values are baked.
- **No mustache pass over CSS/JS.** The deck's stylesheet and script are full of
  braces. Only elements that opt in are touched.

### Formatting is declared, and shared with the site

`data-format` names a formatter from `web/src/lib/format.js` - the module the
Svelte site already uses. One formatter, one meaning, both readers. Add only
what is missing (`usd0`, a signed-percent that emits U+2212).

**The minus sign matters.** The deck uses U+2212 (`−`), not ASCII hyphen. A
formatter emitting `-2.9%` would produce a spurious diff on every run forever.
Pin it in a test.

### Repo facts join the snapshot

`site_export.py` gains a `repo` block, so the answer to "one JSON document" stays
one document:

```json
"repo": {
  "python_lines": 22885,
  "scaffolds": 7,
  "issues_max_id": 125,
  "issues_listed": 75,
  "tests": 745,
  "tests_counted_at": "2026-09-03T18:40:11Z"
}
```

Both issue readings ship, named. The deck then declares which one it means, and
the ambiguity in section 1 cannot recur.

**Cheap facts compute every export** (file reads, milliseconds). **The test count
does not**: `pytest --collect-only` couples publishing the trading record to the
test suite importing cleanly, and `publish.sh` runs on a loop. So it refreshes
only on the release path, carries `tests_counted_at`, and falls back to the prior
snapshot's value otherwise. A repo-fact hiccup must never block a record publish.

## 4. Two paths, because they have different jobs

| | runs | touches tracked files | job |
|---|---|---|---|
| `scripts/publish.sh` (unchanged default) | on a loop | **no** | keep the live site current |
| `scripts/release.sh` (new) | by hand, before submitting | **yes** | refresh the deck source + PDF, reviewably |

`publish.sh` injects into the **static copy only**, so the automated loop causes
zero git churn while the site is never stale. `release.sh` injects **in place**
into `docs/deck.html`, regenerates `docs/deck.pdf`, and prints a per-figure
report - a diff a human reviews before it becomes a submission artifact.

That is the "one command" the request asks for: `./scripts/release.sh`.

## 5. Deliberately NOT doing: a second equity source

"Download all the official figures" could mean calling Alpaca directly for
account equity. **Rejected.** `account.equity` comes from the agent's own
journal, which is reconciled against the broker every tick. A second fetch would
be a second number for one quantity - the exact defect this note exists to
remove, installed by the fix for it.

The honest alternative is to make staleness *visible*, which the deck already
does (`as of 3 Sep 2026, 17:04 UTC · tick 821`). Add one guard: if
`account.as_of` is older than `FRESHNESS_LIMIT_MIN` while the market is open,
warn loudly - the loop is probably down.

## 6. Alternatives considered and rejected

| Alternative | Why it lost |
|---|---|
| **Deck fetches `snapshot.json` at runtime** | The PDF must bake values; `file://` and offline viewing break; 835KB fetched to show 16 numbers |
| **Deck becomes a Svelte route** | Destroys the standalone-document property that is deliberate. Loses the print CSS and the PDF path. Large rewrite, no gain |
| **`{{mustache}}` placeholders in the source** | The source is directly viewable and hosted; placeholders leak to readers. A brace pass over a file whose CSS/JS is full of braces is asking for it |
| **Check-only, keep hand-editing** | Catches drift but still makes a human retype 16 numbers correctly. The retyping is the defect |
| **Inject in place on every publish** | `publish.sh` loops; every run would dirty a tracked file and a tracked PDF |

## 7. Edge cases and required handling

| case | handling |
|---|---|
| Key missing from snapshot | **Refuse.** Non-zero exit naming the key. Never write `undefined` into a submission artifact |
| Value is `null` (e.g. `calibration.reliability` is null today, legitimately) | Keep the baked fallback, **warn**, list it in the report. Null is a real state ("not yet computable"), not a failure |
| `snapshot.json` missing or corrupt | Refuse before touching any file |
| Tagged element contains markup | Refuse, naming the element. Injection assumes a plain-text leaf |
| Injector run twice | Second run reports zero changes. Pinned by test |
| Formatter emits ASCII `-` not `−` | Pinned by test |
| `pytest --collect-only` fails | `tests: null`, prior value retained, publish continues |
| Deck edited but snapshot unchanged | `publish.sh`'s no-op branch is about *the record*. A deck source edit is a deliberate tracked change; `release.sh` forces the deploy |
| Repo facts shrink | Do **not** extend the monotonicity guard to them. Tests and lines legitimately decrease |

## 8. Tests that must exist

In `agent/tests/` for the export side, `web/` for the injector:

- `test_repo_facts_are_computed_and_survive_a_pytest_failure` - repo block
  populates; a raising collector yields `tests: null` and keeps the prior value
- `test_the_monotonicity_guard_ignores_repo_facts` - falling test count does not
  refuse a publish
- `injector: reproduces every current deck figure byte-identically` - the
  section-2 table as a fixture, so a formatter change that would silently
  reword the deck fails here first
- `injector: a missing key refuses and names it`
- `injector: a null value keeps the fallback and warns`
- `injector: running twice changes nothing`
- `injector: the minus sign is U+2212`
- `injector: an element containing markup is refused`

## 9. Rollout

1. **`repo` block in `site_export.py`** + its tests. Nothing consumes it yet.
2. **`web/scripts/inject-figures.mjs`** + `format.js` additions + tests. Run in
   `--check` mode only; it should report the deck as already current, which is
   the acceptance gate.
3. **Tag the deck's ~16 figures.** `--check` still passes; a diff of `data-figure`
   attributes only.
4. **`scripts/release.sh`**, and `publish.sh` injecting into the static copy.
5. **Docs**: `web/CLAUDE.md` gains the figure contract and replaces the hand-run
   PDF command with `release.sh`.

## 10. Deferred

- Injecting figures into `README.md` / `SUBMISSION.md`. Same mechanism, but
  markdown has no attribute to hang the tag on. Wait until a figure there
  actually goes stale.
- A `figures` page on the site listing every tagged figure with its definition.
  Nice, not needed.
